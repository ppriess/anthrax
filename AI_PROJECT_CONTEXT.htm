3. Content origin and provenance

Site content is editorial data assembled for Anthrax Brasil. It includes band information, discography, member/history records, news, official or externally sourced video links, agenda entries, Brazil-specific editorial material, quizzes, navigation, and homepage copy. Individual records may include a source URL, YouTube/Vimeo URL, image URL, or other attribution field.

The versioned JSON files in content/ are the initial and recoverable seed copies of this content. They are not the live production datastore. Some older design copy is illustrative, so factual claims, dates, media ownership, and external links should be verified before publication when adding or revising editorial content.

4. Custom CMS architecture

This project uses a custom-built CMS; it does not use a third-party CMS product such as WordPress, Contentful, or Sanity. The CMS is implemented inside the Next.js application.

  1. Editors authenticate at /admin using the configured ADMIN_PASSWORD.
  2. Authentication creates an HTTP-only session cookie, validated by src/middleware.ts against ADMIN_SESSION_TOKEN.
  3. Admin forms call Next.js server actions in src/lib/admin-actions.ts.
  4. The actions read and write typed JSON documents through src/lib/content.ts.
  5. Runtime JSON is stored as private objects under content/*.json in the Vercel Blob store anthrax-content.
  6. Public pages are dynamically rendered so saved CMS changes can appear without a rebuild.

Running node scripts/seed-content.mjs uploads the repository's content/*.json files and can initialize or reset the Blob content. Editing a repository JSON file alone does not update the live website.

6. Guidance for AI agents

  • Preserve the distinct interface surfaces unless the user explicitly selects, replaces, or retires one.
  • Reuse the shared CMS content model across audience interfaces where practical; avoid hard-coding editorial content into components.
  • For live content changes, work through the custom CMS or explicitly coordinate a seed operation. Repository seed edits and live CMS edits are different operations.
  • Preserve existing uncommitted work. Inspect the working tree before editing overlapping files.
  • Do not expose admin passwords, session tokens, or BLOB_READ_WRITE_TOKEN.
  • Maintain Brazilian Portuguese for public copy unless the user asks for another language.
  • Keep accessibility, responsive behavior, reduced-motion support, media attribution, and factual verification in scope.
